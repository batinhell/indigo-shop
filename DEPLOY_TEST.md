# Деплой тестового стенда — инструкция (ВАЖНО, читать целиком)

Стенд: **https://test.178.20.42.212.sslip.io** (basic-auth, логин `indigo`).
Это отдельный процесс на общем сервере. Прод (`ra-indigo.com`) трогать нельзя.

## ⛔ ГЛАВНОЕ ПРАВИЛО: НИКОГДА НЕ СОБИРАЙ НА СЕРВЕРЕ

У сервера **3.8 ГБ RAM и swap = 0**. `npm run build` / `nuxt build` на сервере регулярно
убивается по нехватке памяти (OOM) **посреди сборки** и оставляет битый `.output`
(нет `server/chunks/routes/renderer.mjs` или пропадает статика) → стенд отдаёт **500/404**.
Это недетерминировано: иногда «проходит», чаще нет. Добавить swap нельзя (нет root).

Поэтому:
- ❌ НЕ запускать на сервере `npm run build`, `nuxt build`, старый «собирающий» deploy.
- ❌ НЕ прогонять вывод деплой-скрипта через `| head` / `| grep -m` — при `set -o pipefail`
  закрытие пайпа шлёт SIGPIPE и обрывает деплой посреди сборки (уже ловили).
- ✅ Собирать **локально** (на маке памяти хватает) и отправлять на сервер **готовый** `.output`.
  Сервер только перезапускает процесс.

## ✅ Правильный цикл деплоя

На своей машине, из корня репозитория:

1. Переключиться на нужную ветку и внести правки вёрстки:
   ```bash
   git checkout feature/моя-ветка
   # ...правки...
   ```
2. Отправить на стенд одной командой (собирает локально → rsync → рестарт):
   ```bash
   ./ship-to-test.sh
   ```
   Скрипт сам: `npm install` + `npm run build` локально → `rsync .output` на сервер →
   `ssh ... deploy-test.sh` (там **только** перезапуск pm2, без сборки).
3. Проверить: открыть https://test.178.20.42.212.sslip.io (обновить Ctrl+Shift+R).

Коммитить `.output` в git **не нужно** — он уходит через rsync, вне git.

## Что на сервере

- Процесс: pm2 `indigo-test`, `node .output/server/index.mjs`, `127.0.0.1:3001`.
- `/var/www/ra-indigo-test/deploy-test.sh` теперь **no-build**: проверяет, что `.output`
  полный, грузит `.env` и делает `pm2 restart`. Если `.output` неполный — честно падает
  с ошибкой и НЕ собирает. Руками его дёргать обычно не надо — его вызывает `ship-to-test.sh`.
- `.env` (вкл. `DATABASE_URL`, `NUXT_PUBLIC_SITE_URL=test-хост`) живёт на сервере, rsync его
  не трогает. БД **общая с продом** — тестовые заказы/оплату не прогонять.

## Если стенд отдаёт 500

Почти всегда это недособранный `.output` после сборки на сервере. Лечение — просто
переотправить корректный билд локально: `./ship-to-test.sh`. Посмотреть причину:
```bash
ssh developer@178.20.42.212 'tail -20 /home/developer/.pm2/logs/indigo-test-error.log'
```
`Cannot find module '.../renderer.mjs'` = битый серверный билд → переотправить.

## Координация

Стенд один. В один момент деплоит **только кто-то один**. Не запускать `ship-to-test.sh`
параллельно с чужим деплоем — иначе `.output` перезатрётся на полуслове.
